# Трекинг плоского объекта на видео по ключевым точкам

Первый кадр видео содержит крупное изображение объекта (эталон). На каждом следующем кадре, где объект виден, вокруг него рисуется рамка с подписью, повторяющая положение и границы объекта.

Python 3, OpenCV, NumPy. Исходный код: [`tracker.py`](tracker.py).

```bash
pip install opencv-python numpy
mkdir out
python tracker.py
```

Параметры (путь к видео, подпись, `BOX` и пороги) задаются константами в начале `tracker.py`.

---

## 1. Теоретическая база

**Ключевые точки и дескрипторы.** Ключевая точка - характерное место изображения (угол, участок с текстурой), которое можно найти повторно при изменении масштаба и ракурса. Её окрестность описывается дескриптором - числовым вектором. Точки на разных изображениях соответствуют друг другу, если их дескрипторы близки. В работе используется **SIFT** [1]: он инвариантен к масштабу и повороту, дескриптор имеет размерность 128.

**Тест Лоу.** Для каждого дескриптора эталона ищутся два ближайших на кадре. Совпадение принимается, если $d_1 < 0.8\,d_2$. Неоднозначные совпадения (например, на повторяющейся текстуре) отбрасываются.

**Гомография.** Плоский объект на кадре связан с эталоном проективным преобразованием - матрицей $H$ размера $3\times 3$ [3]:

$$
\begin{pmatrix} x' \\ y' \\ w' \end{pmatrix} = H \begin{pmatrix} x \\ y \\ 1 \end{pmatrix}, \qquad (u, v) = \left(\frac{x'}{w'}, \frac{y'}{w'}\right).
$$

Достаточно четырёх пар точек. Если применить $H$ к четырём углам эталона, получится четырёхугольник, обрамляющий объект с учётом поворота, масштаба и перспективы.

**RANSAC.** Среди найденных соответствий есть ошибочные. RANSAC многократно строит $H$ по случайным четвёркам пар и выбирает модель, с которой согласуется наибольшее число точек (инлайеры); порог ошибки - 4 пикселя [3].

**Оптический поток Лукаса-Канаде.** Метод находит смещение точки между соседними кадрами, минимизируя разность яркости в окне вокруг неё [2]. Пирамидальная версия позволяет отслеживать большие смещения. Поток быстрее SIFT, поэтому используется как основной способ сопровождения. Надёжность точки проверяется обратным потоком (вперёд-назад): если точка не возвращается на прежнее место (ошибка > 1.5 px), она отбрасывается.

**CLAHE.** Адаптивное выравнивание контраста по плиткам изображения. Увеличивает число ключевых точек в тёмных областях.

## 2. Описание разработанной системы

**Эталон.** SIFT запускается на эталоне в трёх масштабах (1, 0.5, 0.25), координаты точек приводятся к исходному размеру. Когда объект на кадре далеко и мелкий, его точки лучше совпадают с точками уменьшенного эталона.

**Обработка каждого кадра:**

1. **Предобработка.** Перевод в серое, CLAHE.
2. **Оптический поток.** Отслеживаемые точки переносятся с предыдущего кадра на текущий, ненадёжные отбрасываются (проверка вперёд-назад). По оставшимся парам «точка эталона - точка кадра» строится $H$ (не менее 8 инлайеров), углы эталона проецируются на кадр.
3. **Детектирование SIFT.** Запускается, если поток не дал рамки или номер кадра кратен 15. Точки кадра сопоставляются с эталонными (kNN, тест Лоу), RANSAC строит $H$ (не менее 10 инлайеров). Найденные инлайеры становятся новыми отслеживаемыми точками, поэтому накопленный дрейф потока обнуляется.
4. **Проверка рамки.** Четырёхугольник должен быть выпуклым, его площадь - от 0.1% до 400% площади кадра. Относительно предыдущей рамки площадь не должна меняться более чем вдвое, а углы не должны «прыгать» слишком далеко.
5. **Потеря объекта.** Если рамка не найдена, на кадре пишется `not found`, состояние сбрасывается, поиск начинается заново.
6. **Отрисовка.** Рамка сглаживается: $Q_t = 0.7\,Q_{t-1} + 0.3\,Q_{new}$, затем рисуются зелёный контур и подпись.

Тяжёлый SIFT вызывается редко, а между вызовами объект сопровождается оптическим потоком - так программа работает быстро и при этом сама восстанавливается после потери объекта.

## 4. Выводы по работе

1. Реализован трекинг плоского объекта: SIFT-точки эталона сопоставляются с кадром, гомография по RANSAC даёт рамку, повторяющую положение и перспективу объекта.
2. Сочетание SIFT и оптического потока ускоряет обработку: детектор вызывается только при потере объекта и периодически для коррекции дрейфа.
3. Многомасштабный эталон, CLAHE, проверка вперёд-назад и проверка правдоподобия рамки повышают устойчивость при удалении объекта, наклоне и ложных совпадениях.
4. Ограничения: объект должен быть плоским и текстурным; при сильном смазе, большом наклоне и перекрытии объекта точек может не хватить.
